Describe a product once. Check it against each state’s rules.

Cannabis Product Schema is an open JSON Schema for cannabis and hemp product data. The core describes what a product is. Jurisdiction profiles narrow it to what a state allows, and every rule cites the rule text it comes from.

Product data moves between businesses. The rules don’t move with it.

A product’s facts start with a producer and a lab, then pass through distributors, marketplaces and stores. Each system keeps its own shape for them, and each one works out the state’s rules for itself. The schema separates the two: one shared description of the product, and the rules as a separate, cited layer.

  • The core can describe anything

    A product no state allows at retail is still valid core data. The core holds no jurisdiction constants, and the tests check that it stays that way.

  • Profiles only narrow

    A profile restricts what the core allows and never adds fields, so a document that’s valid for a profile is always valid core data.

  • No citation, no merge

    Every profile rule cites primary rule text and comes with a passing and a failing example. The tests prove each failing example trips exactly its rule.

Five objects describe the whole product

A product has one or more packages. Each package carries its own lab result and label. Brands, producers, processors and labs share one shape.

  • ProductA sellable good: its form, brand, regulatory class and packages.
  • PackageThe unit that’s sold: contents, identifiers, prices, its lab result and label.
  • LabResultA certificate of analysis: cannabinoid and terpene readings, pass or fail, test date and public URL.
  • LabelWhat the package says, structured after ASTM D8449’s label modules. Not a conformance claim.
  • PartyA brand, producer, processor or laboratory.

The Georgia profile: five rules, each cited

us-ga-hemp narrows the core to what a Georgia consumable-hemp retailer may sell. It was read from the primary rule text in September 2026, and the numbers live in one config file.

Some rules need a clock

JSON Schema can require a test date, but it can’t tell when one gets old. Rules like that run as small functions under the same rule IDs, so a document can pass today and fail next week without a single change.

Where the rule text says “12 months”, the profile counts 365 days, and says so.

A lab result tested Dec 1, 2025 passes GA-COA-GATE through Dec 1, 2026 and fails on Dec 2: “tested_at is more than 365 days old”.

What it leaves out, on purpose

A product document can’t prove everything the law asks for. The profile lists what it doesn’t check, and why.

Not checked by us-ga-hemp

  • Age 21+. That’s checked at the sale, and a product document has no buyer.
  • The Department-approved warning sticker. A label can carry the warning text, but no data proves a sticker is on a package.
  • Child-resistant, tamper-evident packaging. Verified by inspecting the packaging, not by a field.
  • License numbers and track-and-trace IDs. Stored as text, not looked up.
  • Rule changes after September 2026. Nothing detects an amendment; the profile has to be revised.

What this is not

  • Not “the standard.” It’s one schema, maintained by one company, and doesn’t speak for the industry.
  • Not a consortium or working group. Green Loom maintains it, and decisions are worked out in public issues.
  • Not legal advice. Profiles encode a reading of cited rule text at a point in time. Check current law with your own counsel.

Use it

The current release is v0.1.1. Version 0.x will change, so pin the release you validate against and re-validate when you upgrade.

Point at the hosted schemas

Every schema is served at its $id. These URLs follow the latest 0.1.x release, so they aren’t a pinned copy.

https://greenloom.github.io/cannabis-product-schema/
  v0.1/core/product.schema.json
  v0.1/profiles/us-ga-hemp/product.profile.schema.json

Pin a release and run the tests

Clone a release tag for a copy that won’t change. The suite compiles every schema, checks every example, and confirms each failing example trips its rule.

git clone --branch v0.1.1 \
  https://github.com/greenloom/cannabis-product-schema
cd cannabis-product-schema
npm install
node tests/run.mjs

Propose a profile or a change

Open an issue first. A profile rule needs a citation to primary rule text, plus a passing and a failing example.
